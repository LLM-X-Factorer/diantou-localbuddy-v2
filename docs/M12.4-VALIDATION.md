V5 的本地/模型 Review 顺序为 `parent-retention revise -> parent-retention revise -> semantic accept`。只有最终候选写入 Artifact Registry。运行耗时 147,198 ms，12 次模型调用，132,995 provider-reported tokens；三次工具失败均发生在有界 DOCX 写入链：两次父版本保留退回和一次 80-block 上限，没有再出现 DOCX 正文搜索失败或制表符控制字符失败。

当前父版本保留门槛采用保守的 Revision 语义：父正文达到 1,000 字符时，候选不得低于 50%；父段落达到 10 个时，候选不得低于 80%；章节、表格和表格行数量不得下降。父正文与结构直接提供给 Integrator 和 Reviewer，不再要求它们从 Worker 摘要重建原稿。若用户要大幅删减或重写，应新建 Artifact；未来可再增加显式 replace 模式，而不是猜测用户意图。

DOCX Source 现在可被 `search_source_text` 做单文件有界正文检索；父 DOCX 抽取文本中的 tab-separated 表格可由本地编译器直接还原，不再触发二进制搜索或控制字符误报。

LocalBuddy 的“打开”动作已把 V5 文件交给 macOS Pages，AppleScript 读回两个已打开的同名导入文档；这证明 Pages 接受打开，不冒充逐页视觉排版通过。Goal Contract 折叠也在最终 Renderer DOM 中复验：Composer 高度从 362.883 px 降至 144.695 px，`aria-expanded=false`，输入字段移出 DOM，摘要仍显示结果、约束、验收和资料数量。

### 真实运行中发现并关闭的根因

1. 原故障不是“资料太多”，而是旧恢复语义把整个运行目录做 workspace snapshot；当前只记录明确 Source Set 与真正读过的文件哈希。
2. 只给 Worker 加 Runtime 读取限制不够；若 Prompt 仍展示全局目录，Agent 会浪费 turn 尝试越界读取。现在 Prompt 可见目录与 Runtime 允许目录一致。
3. source-2/3/4 曾被数字闸门误判为除法，URL、斜杠日期和政策原文百分数也属于同类领域语法误判；均已有正向回归。
4. Reviewer 曾把“候选字节已在内存编译、接受后才落盘”误解为“文件尚不存在”；Reviewer 合同现已明确预发布语义。
5. 工具参数 JSON 错误曾错误消耗三次 Reviewer 退回预算；格式修复与语义退回现已分开计数。
6. Worker 输出上限 4,000 tokens 对真实江西长资料不够；Research Agent 统一恢复为 8,000，单次 Agent 仍维持 8 turn 上限。
7. 只把“保留父稿”写进 Prompt 仍会发生整稿缩写；Reviewer 也可能接受。当前把父稿直接交给 Integrator/Reviewer，并用正文、段落、章节、表格和表格行的本地门槛先行拦截。
8. DOCX 抽取文本不是普通 UTF-8 文件，且表格使用制表符表达；`search_source_text` 和 Markdown 编译器必须理解这两个领域格式，不能把它们当二进制错误或不安全控制字符。

## 已验证行为

- Reviewer 以独立 `artifact-reviewer` 身份接收完整目标、Worker 依赖结果和待发布 DOCX 的确定性抽取文本；没有工具和工作区扫描能力；
- 第一个候选缺少显式“风险”要求时，Reviewer 返回一项 finding，文件不落盘；Integrator 第二次补齐后通过，只登记一个最终 Artifact；
- Reviewer 连续三次退回时，Run 失败、Artifact Registry 为空，恢复同一 Run 不会重置预算或产生第四次 Reviewer 调用；
- 无成功最终写入时，Integrator 不能通过纯文本“已完成”绕过 Artifact Gate；
- Reviewer 具体 finding 进入私有 Task checkpoint 给 Integrator 使用，但 Event Store 只保留 verdict、finding 数量和通用失败摘要；专项测试中的私有标记未进入事件或脱敏 trace；
- Desktop 投影能区分 `reviewing / accepted / revision_requested / failed`，并保留审核次数与退回次数；
- `benchmark:trace` 只接受新文件，拒绝写在一次性 workspace 内，也拒绝通过符号链接绕回 workspace；输出文件在 macOS 使用 `0600`，且不包含 Goal、验收文字、错误正文、工作区名称或绝对工作区路径。

## 证据边界

本轮既用确定性 Provider 验证状态与数据边界，也用真实 DeepSeek 对半导体 Research Desk 首版/修订做语义审核。真实案例同时证明 DeepSeek Reviewer 会误接收严重删稿，所以最终通过依赖本地父版本保留门槛、模型 Reviewer 和人工/确定性回读三者共同成立，不能外推为通用复杂文档判定质量。

此前 WB-02 的两次接受、一次失败和一次无结论记录均发生在 Reviewer 之前，不能追溯改写为“已由独立 Reviewer 通过”。

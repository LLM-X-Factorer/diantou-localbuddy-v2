# M10.3 · Provider Setup

## Product decision

Provider 凭据不是高级扩展，而是远程 LLM Run 的必要前置。用户在输入目标之前就应该能回答四个问题：当前选了谁、凭据是否可用、凭据由哪里提供、下一步会不会联网。

因此 Provider 必须有独立、永久可发现的设置入口。Skills、MCP 和 Browser 仍是按 Run 显式启用的可选扩展，二者不能再共享一个含混的“扩展配置”概念。

## Required surfaces

1. 侧边栏提供一级“Provider 设置”，同时显示当前 Provider 的就绪或缺失状态；
2. DeepSeek 与 OpenAI 各自显示 `environment`、`system` 或 `none`，不得返回凭据值、前后缀或长度；
3. 支持向平台凭证库保存新 Key、替换系统 Key，并在 Electron 原生确认后删除系统 Key；
4. 环境变量优先于系统凭据。应用只能报告环境变量存在，不能修改或删除父进程环境；
5. 密码输入只存在于 Renderer 瞬时内存，保存或关闭设置后清空，不进入 local/session storage；
6. Model 与 Base URL 进入 Provider 的“当前 Run 高级设置”；Base URL 继续只允许 HTTPS 或 loopback HTTP，拒绝内嵌凭据、query 和 fragment；
7. Composer 就近显示所选 Provider 状态；凭据缺失时禁止开始并直达设置；
8. 保存只验证本机安全写入，不得自动联网；连接验证和真实 Run 必须是两个不同的显式用户动作。

## Connection verification

“验证连接”是有界认证/网络探针：

- 只有用户点击后执行；
- 使用当前 Provider 与可选 Base URL，GET `<baseUrl>/models`；
- 不调用 chat/completions/responses，不发送用户目标、工作区内容或模型消息；
- 不读取或向 Renderer 返回响应正文；错误只包含 Provider 标签、HTTP 状态或有界的网络/超时分类；
- 保存、删除或验证失败必须在 Provider 对话框内就近显示，不能藏在遮罩后的主界面；
- 10 秒超时，不把 API Key 写入日志、事件、checkpoint 或诊断；
- 成功只证明当时的模型列表端点可认证访问，不等于真实 Run、可用配额或稳定性验收。

## Credential boundaries

- macOS 使用 Keychain，Linux 使用 Secret Service，Windows 使用 Credential Manager；
- Main 进程是唯一凭证读取/写入边界，Preload 只暴露逐项 IPC，Renderer 只接收状态与操作结果；
- 系统凭据删除不能影响另一个 Provider；
- 不把凭据、用户 Prompt、Provider 响应正文或本地事件日志提交到仓库；
- 既有 CLI/Headless Provider 解析顺序保持兼容。

## Explicitly out of scope

- Provider 账号注册、账单、额度或模型推荐；
- 自动探测所有环境变量或自动选择 Provider；
- 保存后自动联网、自动运行或周期性健康检查；
- 回显、复制或导出已有 API Key；
- 把第三方自定义 Base URL 标记为可信；
- 多账号、组织凭据、团队共享或云端 Secret 管理。

## Acceptance

- 没有凭据时可打开完整设置，但不能开始真实 Run；
- 保存后密码框清空、状态变为可用，源码与运行日志中无 Key；
- 替换只作用于所选 Provider；删除必须经原生确认，取消不改变状态；
- 环境变量状态可见但没有应用内删除按钮；
- 连接验证只在点击后请求 `/models`，失败信息不包含响应正文或凭据；
- Extensions 中不再出现 Provider Key/model/base URL；
- Core/Main/Preload/Renderer 类型检查、凭据生命周期测试、连接探针测试、安全合同和真实 Electron 窗口验收通过。

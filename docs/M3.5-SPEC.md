# M3.5 Coding Run Checkpoint Recovery Specification

## 1. 目标与非目标

M3.5 让异常退出的 Coding Run 在安全条件成立时继续使用原 Run ID、原代码计划、原 Agent 消息边界和原 detached worktree，而不是只能从原 Request 全量重放。

本阶段恢复的是本地可证明的执行边界，不恢复 Provider 服务器内部状态，也不降低 M3.2 的人类批准门。checkpoint resume 不会自动把 patch 写回主工作区。

本阶段不提供 CLI `--resume` 命令，不实现 OS/容器级沙箱、自动冲突解决、任意 shell 恢复或已提交结果的一键 revert commit。

## 2. 持久化布局

每个 Coding Run 在 `.localbuddy/runs/<run-id>/` 保存：

```text
run-request.json
events.jsonl
checkpoint/
  coding-manifest.json
  tasks/<task-id>.json
  coding-results/<task-id>.json
  tool-journal.json
artifacts/
  patches/<worker>.patch
  combined.patch
  integration-proposal.json
  artifacts.json
  calculations.json
```

`coding-manifest.json` 固定：

- Run ID、执行模式、规范化 repo 路径和 goal SHA-256；
- baseline HEAD 与校验后的 Coding plan；
- 每个 Worker 的确定性 worktree 路径、task ID、agent ID 和 HEAD；
- 当前 integration preflight attempt；
- 创建与更新时间。

单个 Agent Task checkpoint 保存消息、turn、阶段、工具游标与 Task contract hash。单独的 Coding result 保存控制器已捕获的 Task output、精确 worktree 状态和 patch/Artifact 信息。

JSON 更新采用同目录临时文件加原子 rename。它防止单文件部分写入，但本阶段不承诺断电级 fsync durability。checkpoint 含 Prompt、模型消息、工具结果和本地路径，必须留在被忽略的 `.localbuddy/` 私有目录；API Key 不进入这些文件。

## 3. 两层完成语义

Coding Task 的“完成”必须区分两层：

1. **Agent checkpoint succeeded**：证明模型工具循环已经结束，完整模型 output 已落盘；
2. **Coding Task result completed**：证明控制器已经捕获并登记 patch、保存精确 worktree 状态，相关 Artifact 可复核。

Scheduler 只能根据第二层恢复 `succeeded` Task。第一层成功而第二层缺失时，恢复从控制器阶段继续：复用 Agent output、重新捕获当前 diff、登记 patch 并保存 Coding result，不重复调用模型。

Integrator 同样只有在总结 Artifact 已通过写入闸门、登记并由 Coding result 记录后才可跳过。

## 4. 恢复前不变量

在追加 `run.resumed` 之前必须全部成立：

- `run-request.json` 的 Run、mode、workspace、goal 与恢复请求一致；
- manifest 可解析，计划仍满足 task ID、ownedPaths 不重叠和允许检查命令等 Coding 约束；
- 主仓库 clean，HEAD 精确等于 baseline；
- 每个 Worker path 是 manifest 推导出的确定性路径，目录 realpath 一致，仍登记在 `git worktree list`，HEAD 等于 baseline；
- Agent Task contract hash 与当前 Agent 指令、能力、工具 schema 一致；
- 已完成 Coding result 的 worktree porcelain status 与当前状态一致；
- 当前 binary/full-index diff 的 SHA-256 与已登记 patch 一致；
- patch 文件、Artifact registry 的相对路径、bytes 和 SHA-256 一致；
- Integrator result 指向的 Artifact 仍存在且登记内容一致；
- 不存在只有 started 回执、无法证明是否已产生副作用的写入/执行工具。

任一不变量失败都追加 `checkpoint.resume_blocked`，不追加 `run.resumed`，不修改主仓库或隔离工作树。用户仍可检查现场或选择 M3.3 的从头 replay。

## 5. 恢复矩阵

| 中断边界 | 自动动作 | 理由 |
|---|---|---|
| model request 尚未返回 | 从最后已落盘消息重新请求 | 没有可恢复的远端 continuation token，可能增加一次模型费用 |
| 工具已有 completed 回执 | 返回原结果并追加 `tool.reused` | 避免重复执行 |
| 只读/确定性计算工具只有 started 回执 | 允许重试 | 没有外部副作用 |
| 写入/执行工具只有 started 回执 | 阻断 | 无法证明上次副作用是否发生 |
| Agent succeeded，Coding result 缺失 | 继续本地 patch 捕获与登记 | 模型结果可复用，但控制器产物尚未证明完成 |
| Coding result 完整且复核通过 | Scheduler 直接恢复 output | 工作树、diff 与 Artifact 均可证明 |
| 首个 preview worktree 创建后中断 | 保留旧 preview，启动下一编号 attempt | 不删除事故现场，不与旧事件混淆 |
| Proposal 完整落盘 | 重新校验后恢复 awaiting approval | 预检结果可证明，但批准仍属于人类 |

恢复事件只追加，不重写旧历史。恢复后的 Task 使用原 agentId，worktree 使用原路径；重复中断可以再次按同一协议检查。

## 6. Integration Proposal 幂等性

预检 attempt 使用 `integration-preview`、`integration-preview-2` 等单调编号。中断时不得静默覆盖或删除旧 preview。

完整 Proposal 被视为可恢复前，必须重新验证：

- baseline HEAD 与 patch inventory；
- 每个 patch 的 path、bytes、SHA-256 和 Artifact 登记；
- combined patch 的文件内容与 SHA-256；
- verification command 列表；
- 主仓库 clean 且仍在 baseline。

完全一致时恢复 Proposal 事件投影并停在 `awaiting_approval`；任何不一致阻断恢复。

## 7. applying 中断对账

用户批准时，系统先持久化 `status=applying` 与 approval intent，再产生主仓库副作用。Desktop 读取历史时对 applying Proposal 进行只读为主的精确对账：

- 主仓库仍 clean 且位于 baseline：判定副作用尚未发生，记录 failed/rolledBack；
- baseline 上存在精确等于 approved combined patch 的未提交状态，且变更路径集合完全一致：记录 applied；
- HEAD 是 baseline 的唯一直接后继，commit diff 精确等于 approved patch：记录 committed；
- 其余现场，包括额外 untracked path、不同 diff、多余 commit 或 Proposal 损坏：记录 `recovery_required`。

对账不得执行自动 stash、reset、覆盖或删除。为比较 untracked 文件内容，可以只对 Proposal 批准路径使用 Git intent-to-add；若不匹配必须恢复 index 状态。

## 8. Desktop 语义

Desktop 对异常终止的 Coding Run 展示：

- checkpoint 是否可用；
- 已完成 Coding Task 数与待恢复 Task 数；
- “从 checkpoint 继续”和“从头重新运行”两个语义不同的动作；
- 保留的 Worker/preview worktree；
- Coding 专属说明：恢复会复核 Git 登记工作树、patch 与预检，主仓库不会自动写回。

只有用户点击 checkpoint continue 才产生新的模型费用或继续本地控制器阶段。Replay 创建新 Run；checkpoint resume 保留原 Run ID。

# M3.2 Controlled Integration Specification

## 1. 目标

M3.2 让 M3.1 生成的独立 patch 可以在用户明确批准后安全进入主工作区，同时保证：

- Agent 无法批准自己的修改；
- 多 patch 冲突和组合测试失败发生在主工作区之外；
- 预检后的用户改动不会被覆盖；
- 应用、提交、失败回滚和撤销都有持久事件。

## 2. Integration Proposal

每次成功的 Coding Run 自动创建 integration-preview detached worktree，并依次应用全部 Worker patch。预览必须通过：

1. 每个 patch 的 SHA-256 和 Artifact 路径检查；
2. 每次 `git apply --check --whitespace=error-all`；
3. Planner 声明的组合检查，且必含 `git_diff_check`；
4. 非空 combined patch 与安全 changed paths 检查。

通过后写入 `.localbuddy/runs/<run-id>/integration-proposal.json`，状态为 `awaiting_approval`。Proposal 不保存用户 Prompt，只保存执行与恢复所需的 Git/Artifact 元数据。

## 3. 人工批准

- CLI：只有显式 `--apply` 才构成批准；`--commit-message` 只有与 `--apply` 同时使用才有效。
- Desktop：Renderer 调用逐项 IPC，Electron Main 再展示默认选中“取消”的原生警告框。
- 批准事件记录来源和是否请求 commit，不记录 commit message 正文。

批准后再次验证：

- repoRoot 与 Proposal 一致；
- 主工作区 clean；
- 当前 HEAD 等于 baseline HEAD；
- combined patch 位于本 Run Artifact 目录且哈希一致；
- `git apply --check` 再次成功。

## 4. 应用、commit 与撤销

不提交模式：

- patch 只写入 working tree；
- 当前 Git diff 的 SHA-256 必须等于 approved combined patch；
- 状态进入 `applied`；
- 只有 HEAD 未变且 diff 仍完全一致时才能 reverse apply，成功后进入 `reverted`。

commit 模式：

- 通过 `git apply --index` 原子更新 index 与 working tree；
- staged diff 再运行 `git diff --cached --check`；
- commit message 必须是 1-120 字符的单行文本；
- 使用 `--no-verify --no-gpg-sign` 避免未经建模的 hook 与交互式签名；
- commit 成功后记录 SHA，状态进入 `committed`。

如果 apply 后的验证或 commit 失败，控制器只恢复 Proposal 声明的 changed paths。恢复成功为 `failed + rolledBack=true`；恢复失败进入 `recovery_required`，不伪装成安全失败。

## 5. 并发与审计

- preflight 使用独立 isolationKey，但仍占共享 ExecutionCoordinator 容量。
- apply、commit、revert 必须获取主工作区独占写 lease。
- integration 事件进入同一 append-only JSONL，Desktop 重启后可以恢复审批状态。

## 6. 非目标

- 不自动解决 patch 冲突。
- 不对脏工作区自动 stash、reset 或覆盖。
- 不对已创建 commit 自动执行 `git revert`。
- 不保证不可信项目脚本、Git filter 或其他仓库配置的 OS 安全。
- 不自动删除 Worker 或 preview worktree。

## 7. Git 依据

- `git apply --check` 只验证而不应用；默认情况下任一 hunk 失败会让整份 patch 不写入工作区：<https://git-scm.com/docs/git-apply>
- `git apply --index` 同时更新 index 与 working tree，并要求两者相关路径起点一致：<https://git-scm.com/docs/git-apply>
- `git restore --staged` 可把指定路径的 index 内容恢复到 HEAD，M3.2 只在已核对范围内用于失败恢复：<https://git-scm.com/docs/git-restore>

## Defects found and fixed

### 1. DMG corrupted framework symlinks

`scripts/make-dmg.mjs` copied the `.app` without preserving symlinks verbatim. Relative framework links became absolute links to the local Forge output. The copy now uses `verbatimSymlinks: true`, and package verification mounts the DMG, verifies the mounted app, and rejects unsafe symlinks. This defect invalidates the historical M10 DMG even though `hdiutil verify` had passed.

### 2. Workspace process-lock release/reacquire race

The first full check exposed a transient missing `runtime-lock` during parallel Desktop operations. Final release left a zero-reference entry discoverable while asynchronous cleanup was still running. The lock manager now removes the held entry before cleanup, tracks pending releases, and makes reacquisition await final cleanup. A 20-iteration release/reacquire regression test was added.

### 3. Deterministic calculation ID conflicted across Agents

Calculation IDs intentionally hash the tool input and result, but the JSON registry compared the full record, including Task and Agent provenance. The same correct calculation repeated by another Agent therefore raised a conflict and caused avoidable retries or Run failure. Both registries now reuse identical calculation evidence across provenance while still rejecting a different result under the same deterministic ID. Two registry tests and the installed-app three-Agent regression prove the fix.

## Failures and friction kept visible

- Before the calculation fix, `run-c9a8f86f-7aa8-4afc-a930-b35a40f414a3` failed after 158 events because repeated exact calculations conflicted; another Run succeeded only after costly retries. These failures are not counted as passes.
- The first extension attempt, `run-fdea765c-b130-4968-8351-c2baff17f5df`, failed before planning with only `MCP error -32000: Connection closed`. The M10.1 diagnostics fix prevents future failures from losing every child-process clue, but historical events are intentionally not rewritten.

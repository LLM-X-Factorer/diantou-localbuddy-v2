# M12.2 Artifact Thread History + Verified Text Diff Specification

> 状态：2026-08-15 本地实现候选，尚未发布。  
> 范围：在 M12.1 的父 Artifact 身份之上增加版本/尝试列表和直接父版本文本 diff；不声称已经具备通用 Project Thread 或 Office 编辑器。

## 1. 用户问题

M12.1 能显示当前版本和直接父版本，但用户仍然无法回答三个产品问题：

1. 同一个 Artifact 到底经历了哪些成功、失败、replay 或分支尝试；
2. 当前版本具体增加、删除了什么，而不是只看“修改原因”；
3. 历史文件被移动或改写后，界面是否还会把它伪装成可用版本。

M12.2 把 Artifact 面板升级为最小 Workbench。它只读取 `.localbuddy/runs` 中已登记的 Run/Event/Artifact Registry，不枚举或扫描普通工作区文件。

## 2. Thread History 合同

Renderer 通过当前已验证 Artifact 的 Run ID 和相对文件名请求历史。Main 先复核当前 Artifact，再从审计事件投影中汇总相同 `threadId`：

- V1 根版本来自第一条 revision 的不可变父 Run、父文件和父 SHA-256；
- 后续 Run 使用其持久化 revision、状态、修改原因、父身份和已登记产物；
- failed/replay 或同 revision 分支不会互相覆盖，而是作为同版的不同尝试显示；
- 每个历史 Artifact 都单独复核 Registry、真实路径、bytes 和 SHA-256；
- 复核失败的历史仍留在列表中，但标为“校验不可用”，按钮禁用；
- 单个 Thread 最多展示 200 个 revision Run，每个 Run 最多展示 20 个 Artifact；超过上限明确报错，不静默截断历史。

没有后续 revision 的普通 Artifact 也可以形成只含 V1 的稳定身份；一旦用户以后发起修订，Thread ID 与这个身份一致。

## 3. Verified Text Diff

“与上一版比较”只比较当前 revision Run 的已验证文本 Artifact与合同中记录的直接父 Artifact：

- 两端都必须重新通过 Artifact Gate，父 SHA-256 必须与 revision 合同一致；
- V3 及以后必须能读取父版本 revision 合同，并满足相同 Thread、版本号严格递增 1；缺失或冲突时 fail closed；
- 当前支持 `.md`、`.json`、`.txt`、`.patch`、`.diff`；不把二进制 Office 文件当文本；
- 单文件上限 200,000 bytes、4,000 行；LCS 计算上限 2,000,000 cells，超出后使用共同前后缀的有界替换视图；
- 最多渲染 2,000 行 diff，保留增删总数并明确标记显示截断；
- CRLF/CR 在文本比较时统一为 LF，避免只因平台换行产生整篇噪声。

Diff 只在本机 Main/Core 计算，不调用 Provider，不写回 Artifact，也不改变 Thread 历史。

## 4. Desktop 表现

- 用户打开一个 Artifact 后看到 Thread ID、V1/V2/... 历史、Run 状态、修改原因和每个已验证文件；
- failed/replay 在同一 revision 下显示为不同分支/尝试；
- 点击任一可用历史文件会切换到对应 Run 并打开经校验的预览；
- 当前 revision 的文本 Artifact 提供“与上一版比较”；增行绿色、删行红色，同时显示父/当前行号；
- 父版本发生漂移时，历史项降级为“校验不可用”，diff 请求显示原始安全错误，不展示未经验证内容。

## 5. WB-02 边界

M12.2 为 WB-02 第二轮修改补齐了 Thread、上一版可恢复和文本差异底座，并新增 [`expected-facts.json`](../benchmarks/workbuddy-core/cases/WB-02-document-revision/expected-facts.json) 事实真源。

WB-02 仍是 `blocked`：当前 Artifact Gate 不生成或复核可编辑 DOCX。Markdown 版本历史不能替代题目要求的 DOCX 打开、编辑、表格和版式验收。解除条件见 [`READINESS.md`](../benchmarks/workbuddy-core/cases/WB-02-document-revision/READINESS.md)。

## 6. 本切片明确不包含

- 跨工作区 Project/Thread 搜索、重命名、归档或云同步；
- 完整分支图、版本合并、任意两版比较或语义 Reviewer；
- HTML 渲染预览、图片/PDF diff、DOCX/XLSX/PPTX 打开与编辑；
- Goal revision 2+、运行中 steering 或自动选择“最佳版本”；
- WorkBuddy 黑盒实跑或 LocalBuddy WB-02 通过结论。

下一切片应优先做 Office Artifact 能力分诊：先让 DOCX 产物可真实创建、打开、抽取复核和二次修改，再运行 WB-02 pilot，而不是用扩展名或 Markdown 冒充通过。

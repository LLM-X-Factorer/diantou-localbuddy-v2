# M12.2 Artifact Thread History + Verified Text Diff Validation

> 验证时间：2026-08-15
> 结论：源码候选在 macOS 开发构建、确定性自动门禁和真实 Electron 界面中通过；WB-02 仍因缺少真实 DOCX 创建、打开和复核能力而保持 `blocked`，本轮尚未打包或发布。

## 验收范围

本轮验证同一 Artifact Thread 的版本/尝试列表、历史文件逐项校验、直接父版本文本 diff，以及历史文件漂移后的安全降级。数据全部来自独立临时工作区内的合成 Markdown 产物，没有调用真实 Provider、外部工具或用户工作区资料。

环境：macOS 26.5（arm64）、Node.js v25.8.2、pnpm 9.15.9；Desktop 开发构建使用仓库锁定的 Electron 43.3.0。

## 自动门禁

| 检查 | 结果 |
| --- | --- |
| `pnpm check` | 173 tests；171 passed；2 个 Windows-only 合同按 macOS 平台跳过；0 failed |
| `pnpm build` | Renderer 18 modules 构建成功；Core TypeScript 构建成功 |
| `git diff --check` | 通过 |

确定性覆盖包括：

- 同一 Thread 汇总 V1、V2、失败尝试和 replay；同 revision 的多次尝试不会互相覆盖；
- 历史读取仅遍历 `.localbuddy/runs` 中的审计记录和 Artifact Registry，不扫描普通工作区文件；
- 每个历史 Artifact 独立复核注册路径、bytes 和 SHA-256，漂移文件保留历史身份但降级为“校验不可用”；
- 直接父版本 diff 同时复核当前和父 Artifact，并验证父 SHA-256、Thread ID 和连续版本号；缺少 V3+ 父 revision 合同时 fail closed；
- 文本 diff 统一平台换行，并对文件字节数、行数、LCS 单元数和渲染行数设置明确上限；超过精确 LCS 上限时使用有界前后缀比较；
- 新增 WB-02 事实真源和 readiness 门禁；测试禁止把当前 `blocked` 状态写成“已经通过”。

## macOS 真实界面读回

使用当前源码完成 `pnpm build` 后，以独立临时 user-data 和完全合成的两版 Markdown Artifact 启动开发版 Electron。没有操作已安装版 LocalBuddy，也没有触发模型、Provider 或工具调用。

实际读回结果：

1. 打开 V2 Artifact 后，Workbench 显示稳定 Thread ID、V1/V2、对应 Run 状态、修改原因、文件名和哈希摘要；
2. 点击“与上一版比较”后，界面显示 `V1 -> V2`、父/当前文件名、`+7 / -3`，删除行以红色、增加行以绿色呈现，并保留两侧行号；
3. 从 V2 历史点击 V1，可切换到 V1 Run 并打开经 Artifact Gate 校验的旧版；再从 V1 历史点击 V2，能正确返回新版，未出现跨 Run 状态覆盖；
4. 在临时工作区改写 V1 文件但不更新 Registry 后，V1 仍保留在历史列表中，但入口变为“校验不可用”；
5. 此时请求 diff 会显示 `artifact content no longer matches its registered size and SHA-256`，未展示已经漂移的父内容；
6. 开发进程退出后，两个临时测试目录已精确删除。

这次真机读回还验证了一个容易被单元测试遗漏的交互边界：跨 Run 打开历史版本时，必须等待 React 完成 selected-run 状态切换后再加载预览和 Thread，否则清理 effect 会抹掉刚加载的数据。实现已按该边界修正并纳入最终构建。

## WB-02 准入结论

M12.2 只补齐了版本身份、历史恢复和文本差异底座。WB-02 要求真实 DOCX 产物能够创建、打开、编辑、抽取复核并在第二轮修改后保持表格与版式；当前系统尚不具备这条完整链路。因此：

- readiness 状态保持 `blocked`，不计分、不写“通过”；
- Markdown 或把文件扩展名改成 `.docx` 都不能代替验收；
- 下一步应先实现最小 Office Artifact 纵向切片，再运行 LocalBuddy WB-02 pilot。

## 尚未证明

- 没有生成 DMG/ZIP，也没有验证已安装 App、签名、自动升级或发布资产；
- 没有运行 WorkBuddy 客户端黑盒案例，不能声称产品能力已经达到 WorkBuddy；
- 没有 DOCX/XLSX/PPTX 的原格式编辑、渲染与版式验收；
- 没有任意两版比较、版本合并、完整分支图或语义 Reviewer；
- 没有真实 Provider 的长文修订质量、成本和连续 dogfood 证据。

本轮的准确结论是：M12.2 的本地文本 Artifact Thread 与安全 diff 已成为可运行候选；Office Artifact 是进入 WB-02 实测前的硬门槛。

## Windows/Linux synchronization boundary

- `package.json` 的 `0.11.1` 是三平台唯一版本真源；Windows Setup 文件名也从该版本派生；
- Linux DEB 显式依赖 Ubuntu/Debian 的 [`libsecret-tools`](https://packages.ubuntu.com/noble/libsecret-tools)，确保安装 `secret-tool` CLI；实际 Secret Service 仍要求可用的图形桌面会话；
- `main` CI 的 Windows/Linux 平台合同新增 Provider 凭据生命周期和非生成式连接探针测试；
- `v*` Tag workflow 分别在 `windows-2025` 与 `ubuntu-24.04` 构建 Setup/ZIP 和 DEB，生成独立 LF SHA-256 清单；
- Windows 原生构建与 Tag Release 都在打包后执行无 Provider 凭据的真实 Electron 首次启动 smoke，并保存截图/JSON 证据；
- 两个原生发布作业都先运行 `pnpm audit --prod --audit-level high`，阻止带已知高危运行时依赖的资产进入 Release；
- 发布作业校验 Tag 与 `package.json` 一致，并只在两个原生构建均成功后一次性发布全部资产；
- workflow YAML 解析、版本命令和静态发布合同已在 macOS 本机通过；没有 commit/Tag/push，因此不能宣称 `0.11.1` Windows/Linux 原生产物已经生成。

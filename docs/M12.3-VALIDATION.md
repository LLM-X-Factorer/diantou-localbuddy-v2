# M12.3 Bounded DOCX Artifact + WB-02 Pilot Validation

> 验证时间：2026-08-15
> 结论：受限 DOCX 纵向链路在 macOS 开发构建、确定性产品 pilot、Pages 实际打开和 Electron Artifact Workbench 中通过，后来随公开但未签名的 `v0.12.4` Engineering Alpha 发布。真实 DeepSeek 两轮记录为 2 次接受、1 次失败和 1 次 grader 缺陷导致的无结论运行；WB-02 状态仍为 `provider-stability-not-passed`，不是 `passed`。本文的运行不是安装包验收，也未运行 WorkBuddy 黑盒。

## 验收环境与范围

环境为 macOS 26.5 arm64、Node.js v25.8.2、pnpm 9.15.9 和仓库锁定 Electron 43.3.0。所有业务内容来自 WB-02 合成夹具；没有读取用户业务目录或提交 Prompt/事件日志。最终 Provider pilot 使用系统安全存储中已配置的 DeepSeek 凭据并产生真实模型调用。

本轮分别验证：DOCX 结构编译与安全解析、Research Source 读取、Artifact Gate、两轮 revision、版本历史与差异、macOS Pages 视觉结果、历史文件漂移后的 fail-closed，以及真实 Provider 波动时的失败可观测性。

1. 第 1 页包含标题、副标题、三项元数据、59 字执行摘要和四项决定；中文、项目符号和换行可见，无观察到截断或重叠；
2. 第 2 页包含 7 行 × 3 列的行动项表、5 行 × 3 列的预算表、四项风险/边界和文末“本轮修改说明”；
3. 表格列头、六个行动项、四个预算数字和“待确认”均完整可见，页码 1/2 正常；
4. 文档关闭时未出现保存提示，临时文件与目录随后精确删除。

本机未安装 LibreOffice，因此没有把 Pages 结果写成 LibreOffice 或 Windows Word 已通过。

## Electron Artifact Workbench 实测

当前源码构建后，以独立临时 workspace 和 user-data 启动 Electron，并用确定性 Provider 生成同一 Thread 的 V1/V2 DOCX：

- V2 面板显示版本 2、父文件/哈希/修改原因、DOCX 文件名/大小/哈希和结构统计；
- 结构预览从 OOXML 本机抽取，事件轨迹显示 `write_docx_artifact` 请求、获准、产物生成和完成；
- “与上一版比较”显示 `V1 -> V2 DOCX 正文/表格差异`；
- 从版本历史可切到 V1，再返回 V2；历史读取明确标记“不扫描工作区”；
- 故意改写临时 V1 但不更新 Registry 后，V1 入口变为“校验不可用”，预览与 diff 返回 `artifact content no longer matches its registered size and SHA-256`，没有展示漂移后的内容；
- Electron 退出后，临时 workspace、user-data 和夹具脚本已精确删除。

Electron 功能读回发生在最终 WB-02 夹具补齐首轮摘要/风险之前；最终内容完整性由随后 30/30 专项回归和上述 Pages 逐页检查覆盖。这里不把两个不同门禁混写成一次运行。

## 真实 DeepSeek 两轮运行

使用全新临时 workspace、两份合成资料、真实 Plan Review 和系统安全存储中的 DeepSeek 凭据运行 manifest 原始两轮任务。运行只输出脱敏统计与 grader 布尔值，结束后删除 Run、Prompt、产物和协调账本所在临时目录。

前置 pilot 暴露并修复了两个通用断链：第二轮没有重复写“DOCX”时 Planner 会改成 Markdown或省略文件名；Integrator 只看到 Planner 摘要而没有再次看到完整 Goal Contract。修复均落实为运行时合同和确定性回归，不把 WB-02 事实硬编码进提示词。

第一条接受运行结果：

| 轮次 | 状态 | 模型调用 | Provider-reported tokens | Artifact |
| --- | --- | ---: | ---: | --- |
| V1 | succeeded | 10 | 19,861 | `项目启动纪要.docx`，6 个章节，1 个表格 |
| V2 | succeeded | 9 | 28,931 | 同名 DOCX，7 个章节，1 个表格 |

自动 grader 确认 V1 含执行摘要和风险；V2 含全部四项决定、六项行动及日期/“待确认”、四项风险/边界、120,000 / 70,000 / 30,000 / 20,000 四个预算数，执行摘要为 115 个字符，最后章节为“本轮修改说明”。Thread 读回 `[1, 2]`，DOCX 结构差异非空。

随后从全新临时目录执行两次稳定性运行，并在修复 grader/可观测性后增加一次明确标记的诊断运行；没有用重跑覆盖失败：

| 记录 | 结论 | V1 | V2 | 关键证据 |
| --- | --- | --- | --- | --- |
| 接受 pilot #1 | accepted | 10 calls / 19,861 tokens | 9 calls / 28,931 tokens | V2 摘要 115 字；全部检查通过 |
| 稳定性 #2 | failed | 14 calls / 42,073 tokens / 6 tool failures | 未启动 | V1 没有 Artifact；无模型失败 |
| 稳定性 #3 | inconclusive | 11 calls / 20,296 tokens | 6 calls / 17,040 tokens | V1/V2 succeeded；旧 grader 对带序号标题产生假阴性 |
| 诊断 #4 | accepted | 11 calls / 19,700 tokens | 6 calls / 21,312 tokens | V2 摘要 100 字；全部检查通过 |

稳定性 #3 的旧 grader 用 `##` 后必须紧跟“执行摘要/风险”的正则检查 V1，却用可包含编号的规则检查 V2。真实 V2 在 Pages 中显示“一、执行摘要”“五、风险”，证明该规则会误伤正常编号标题。V1 已按隐私策略随临时 Run 删除，不能事后改判，因此保留为 `inconclusive`，不算产品失败，也不算通过。

稳定性 #2 是真实失败：模型调用成功，但 6 次工具调用失败后 V1 终止。旧版 Run 投影没有把 `write_docx_artifact` 纳入 Artifact Gate retry，也没有把 Scheduler 的 Task error 带到顶层 `run.failed`；临时事件目录删除后不能准确重建六次工具失败的类型。源码候选随后修复这两个通用可观测性缺口并增加回归：

- 文本/DOCX 最终写入工具失败统一计入 `artifactGateRetries` 和 `artifact_gate` failure stage；
- DOCX `tool.failed` 最近事件展示截断后的具体错误，不再只显示工具名；
- Research 与 Coding 的终态 `run.failed` 带上首个失败 Task 及其原因；
- 诊断 #4 的 V1 仍有 2 次非 Artifact 工具失败，但 Agent 自行恢复并成功；V2 无工具失败。这里不能据此倒推稳定性 #2 的精确根因。

## 真实 Provider DOCX 的 macOS Pages 视觉检查

稳定性 #3 的 V2 在清理前复制到独立 QA 临时目录，并通过 Pages 原生打开。Pages 识别为 Microsoft Word 文稿并分页为三页：

1. 第 1 页包含标题、会议元数据、103 字执行摘要、决定和行动项表前半部分；
2. 7 行 × 4 列行动项表跨第 1/2 页，第二页重复列头；六项行动、负责人、日期和“待确认”完整可见；
3. 第 2 页包含四个预算数、孙至书面确认约束、风险与采购边界；
4. 第 3 页包含文末“本轮修改说明”和页码 3；没有观察到截断、重叠、乱码或边框破损，但正文只占页面上部，留白明显，版式为“可用但未达到精致交付”；
5. 关闭时没有保存提示；真实产物和 QA 临时目录随后精确删除。

本机没有 LibreOffice；该证据是 Pages/macOS 证据，不代表 LibreOffice 或 Windows Word。

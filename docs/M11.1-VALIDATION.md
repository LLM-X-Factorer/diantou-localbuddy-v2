# M11.1 Goal Contract + Plan Review Validation

> 日期：2026-08-14。状态：`local implementation, macOS package and installed synthetic gray validated; Windows release gates pending`。本文只记录已经完成的证据，不把尚未运行的 Tag workflow 写成成功。

## 1. 当前结论

M11.1 的本机代码合同成立：Desktop 在 Orchestrator 生成计划后等待人工决定，批准前没有 Worker 或 Coding worktree；拒绝会结束 Run；pending 决定可以跨 Desktop 重启恢复。CLI/Core 的非交互调用保持兼容。

它尚不是完整 M11：没有编辑计划、Goal revision 2+、steering、独立 Reviewer 或 Eval promotion gate。

## 2. 自动化证据


两项跳过均为 Windows-only platform contract。新增重点用例覆盖：

- Desktop 只完成一次 Planner 调用即进入 Plan Review，批准前 `task.started=false`、`workspace.created=false`；
- 批准事件严格早于第一个 Worker 启动事件；
- 拒绝计划后 Run 为 `cancelled`，Provider 调用数仍为 1；
- pending `plan-review.json` 经模拟 Desktop 重启、`run.interrupted` 对账和 same-Run resume 后仍可批准；
- Review digest 绑定 Goal、Plan 和 scope，计划文件名被静默改动时拒绝复用批准；
- Desktop IPC 无法绕过页面提交没有完成标准的 Goal Contract；
- 决定已落盘但审计事件第一次写入失败时可以安全重试；重启恢复会补记缺失的决定事件，再继续或结束 Run；
- Run Request v5 保存结构化 Goal，v2 历史仍以原文本恢复且不重写；
- 旧无结构字段的执行文本保持原样，既有 Research/Coding checkpoint 恢复矩阵继续通过；
- 1,050 个无关文件的 Research Run 恢复回归继续通过。

`pnpm build` 同日通过 Renderer Vite 生产构建和 Core TypeScript 构建。

## 5. macOS 最终 App 合成灰度

最终打包的 arm64 App 使用隔离 user data、临时 OpenAI 环境凭据和只监听 `127.0.0.1` 的确定性 Provider 完成安装版纵向验收；没有调用真实 Provider，也没有改写系统凭据：

- 实际页面显示 pending Plan Review，并从页面点击“批准，开始 Worker”；
- 成功 Run 产生并登记 Markdown Artifact，计划卡、任务图和事件轨迹可见；
- 两个 Run 可同时活动并从页面/API 取消，夹具确认 2 个 Worker 请求收到中断；
- 集成阶段被强制中断后，App 重启将 Run 对账为 `interrupted`，same-Run checkpoint resume 最终成功；
- 成功历史跨重启保留；临时凭据未出现在 `events.jsonl` 或 `run-request.json`；
- 回环夹具统计为 1 次 models probe、13 次 completion、2 次取消、1 次恢复中断；成功页与取消页截图已目视核对，证据位于 Git 忽略的 `.localbuddy/m11.1-macos-installed-gray/`。

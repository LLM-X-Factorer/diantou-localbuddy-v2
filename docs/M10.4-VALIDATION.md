# M10.4 Validation Record

Date: 2026-08-14, Apple Silicon macOS 26.5.

## Scope

M10.4 fixes the product contract behind `workspace snapshot exceeded the safe checkpoint entry limit`. The old Research runtime treated the selected workspace as both run storage and an implicit evidence repository, then hashed the whole directory for recovery. The new contract separates:

- **Run location**: append-only events, checkpoint metadata and Artifacts under `.localbuddy/`;
- **Selected sources**: only files or directories explicitly added for this Run;
- **Read evidence**: only successful `read_file` receipts are re-hashed before resume.

This is an independent LocalBuddy implementation. Public Codex product behavior informed the boundary, but no external implementation source, UI asset, product string or Git history was copied.

This private build accepts the already documented clean-runner packaging risk and does not claim the advisory is fixed;
- `git diff --check`: passed before handoff.

The regression matrix proves:

- a failed Research Run resumes successfully with 1,050 unrelated files in its run directory;
- unreadable unrelated files do not block planning or history inspection;
- changing, moving or deleting a file actually read by the Run blocks resume;
- changing unrelated run files or unconsumed selected sources does not block resume;
- no selected sources means no local search/read tools and no project path in planner context;
- selected directories are searched only after a non-empty filename query, with 50 result and 10,000 examined-entry bounds;
- symlinks, `.git`, `.localbuddy` and `node_modules` are excluded from Research source discovery;
- legacy v1-v3 implicit-workspace Research requests are not silently replayed under v4 semantics.

# M12.3 Bounded DOCX Artifact + WB-02 Pilot Specification

> 状态：2026-08-15 本地实现候选，尚未发布。
> 范围：让“生成 DOCX → 打开复核 → 基于同一产物修订 → 比较版本”成为受限但可信的纵向链路；不声明通用 Word 编辑器能力。

## 1. 产品目标

M12.1/M12.2 已能证明一个 Artifact 的父子身份、历史和文本差异，但 WB-02 的核心交付是可编辑 DOCX。只写 Markdown、改扩展名或让模型直接拼 OOXML 都不能满足这个产品结果。

M12.3 采用“模型表达内容，本地编译文件”的边界：

```text
明确 DOCX 目标
  -> Integrator 输出有界 Markdown 内容
    -> Core 解析为受限段落/项目符号/表格结构
    -> Core 确定性生成 OOXML
      -> Core 从生成包回读正文/表格并逐字核对
        -> 原子写入 + Artifact Registry
          -> Desktop 结构预览 / 系统打开 / 版本比较
```

## 2. 生成合同

只有 Integrator 可以调用 `write_docx_artifact`。Provider-facing 工具只接收一个有界 Markdown `content` 字符串，不接收嵌套文档 JSON、原始 XML、ZIP 或 HTML。支持一行 `#` 标题、`##` 章节、普通段落、`-` 项目符号、pipe table，以及修订父 DOCX 抽取文本中的 tab-separated table。Core 再把它解析为版本为 1 的受限结构：

- 标题、可选副标题和最多 10 项元数据；
- 最多 20 个章节、80 个内容块；
- 内容块只允许段落、项目符号和表格；
- 表格最多 100 行、8 列，每行必须与表头列数一致；
- 历史 checkpoint/test 使用的结构化输入仍可由本地 parser 读取，但不再暴露给 Provider，避免大段嵌套 JSON 参数反复格式失败。

生成器固定 ZIP 时间和 Core 文档元数据，相同结构产生相同字节。页面采用 Letter 竖版、1 英寸页边距、Calibri/PingFang SC 字体、真实项目符号编号、内容感知列宽、重复表头和页码。表格总宽固定，不能依靠 Word 自动猜测列宽。

写入前执行三道检查：规范化并限制结构、生成后从 DOCX 回读规范文本、回读结果与预期逐字一致。最后使用临时文件和 rename 原子落盘，并登记媒体类型、bytes、SHA-256 和文档统计。

## 3. 读取与安全合同

DOCX 只在用户明确选择为 Source 或从已登记 Artifact 打开时读取。它不是通用附件扫描器。

- 压缩包最大 5 MB，单条目最大 5 MB，展开总量最大 20 MB，最多 256 个条目，规范文本最多 120,000 字符；
- 路径逃逸、重复条目、异常展开大小和非标准 Word 主内容类型均拒绝；
- 宏、VBA、任意 `.rels` 中的外部关系、ActiveX、嵌入对象、图片、页眉、正文型页脚、批注、脚注/尾注、修订痕迹、隐藏文字、字段代码、文本框、内容控件及 alternate content 均 fail closed；
- 当前只抽取标题、章节、普通段落、项目符号和表格行；不尝试把未支持内容静默丢失后继续修改。

恢复和修订仍遵守 M12.1/M12.2：父 Artifact 必须重新通过 Registry、真实路径、bytes 和 SHA-256 校验，再复制为新 Run 的只读 Source 快照。不会扫描普通工作区寻找“同名 Word 文件”。

## 4. Desktop 合同

- Artifact 卡片标记 `DOCX`；Main 在本机抽取正文和表格，Renderer 只接收结构化预览结果；
- 预览明确显示章节、段落、表格和表格行统计，并提示分页/视觉版式必须用“系统打开”检查；
- 系统打开、历史切换和继续修订前都重新复核 Artifact；
- V2 与直接父 DOCX 比较时，两端必须同为 DOCX、通过哈希校验且版本身份连续；比较对象是规范化正文/表格文本，不冒充像素级或 Word 修订痕迹 diff；
- 被移动或篡改的历史项仍保留审计身份，但显示“校验不可用”，预览和比较拒绝。

## 5. WB-02 验收合同

确定性 pilot 必须走真实 DesktopRunManager、Planner、Worker、Integrator、Artifact Gate 和 revision Thread，而不是直接调用生成器：

- V1 已经满足首轮执行摘要、四项决定、六项行动、预算、风险与不确定边界；
- V2 将执行摘要压缩到 120 字以内，保留每项唯一负责人和来源日期，缺失日期写“待确认”；
- V2 文末新增“本轮修改说明”，V1 可恢复，直接父版本可比较；
- 事实和数字由 [`expected-facts.json`](../benchmarks/workbuddy-core/cases/WB-02-document-revision/expected-facts.json) 逐项评分。

Revision Run 默认继承已验证父 Artifact 的文件名和格式。第二轮不需要重复说“DOCX”；即使 Planner 省略或误写 `integration.fileName`，控制器也使用父合同。Integrator 必须重新收到完整 Overall Goal Contract，并保留未被本轮明确要求修改的父内容。

通过确定性 pilot 只进入 Provider pilot；一次 Provider 通过也不等于正式通过。三次独立运行、人工评分、Windows Word 和 LibreOffice 仍是独立门禁。

## 6. 明确不包含

- 任意现有 DOCX 的保真编辑、模板套用、样式继承或 Word 修订痕迹；
- 图片、图表、公式、目录、链接、批注、页眉页脚内容编辑或嵌入文件；
- PDF/XLSX/PPTX；
- 像素级版式 diff、语义 Reviewer 或任意两版合并；
- WorkBuddy 黑盒通过、Git 提交、Tag、安装包或 Release。

# M12.4 Independent DOCX Reviewer + Retained Benchmark Trace Specification

> 状态：已随公开但未签名的 `v0.12.4` Engineering Alpha 发布；Reviewer 仍只覆盖受限 DOCX，产品稳定性由 M13 验证。

## 1. 产品目标

M12.3 已能确定性生成和回读受限 DOCX，但“文件结构合法”不等于“内容满足用户目标”。M12.4 增加一个与 Integrator 分离的只读 Reviewer，在 DOCX 真正写入和登记前比较原始 Goal Contract、Worker 证据与候选文档正文。

本切片同时补齐 benchmark 失败留证：一次性工作区清理前，可把脱敏 trace 导出到工作区之外。它保留定位问题需要的计数和状态，但不复制 Goal、模型正文、工具参数、Artifact 正文、凭据或绝对路径。

## 2. Reviewer 合同

Reviewer 不是新的写入 Agent，也不能修改候选文件。DOCX 写入顺序固定为：

```text
Integrator bounded Markdown candidate
  -> local bounded DOCX structure
  -> deterministic normalization / calculation gate
  -> local OOXML compile + structural round-trip
  -> candidate bytes + SHA-256 + extracted visible text
  -> independent read-only Reviewer
       -> accept: atomic write + Artifact Registry + artifact.created
       -> revise: private feedback to Integrator, no file published
```

Reviewer 使用同一 Run 已选择的 Provider，但以独立 `artifact-reviewer` 身份调用，不带工具。输入只包含：

- 完整 Goal Contract；
- Integrator 的直接依赖结果，即 Worker 已交付的证据摘要；
- 待发布 DOCX 的文件名、media type、bytes、SHA-256、结构统计和确定性抽取文本；
- 修订 Run 还包含 Main 进程已复核 SHA-256 的父 DOCX 抽取正文和结构统计；Integrator 也直接收到同一父版本，不得从 Worker 摘要重建原稿。

Reviewer 不扫描工作区，也不重新打开未选择资料。Goal 上限沿用现有 20,000 字符合同；Worker 证据合计最多 40,000 字符；候选正文和修订父正文各最多 80,000 字符。超限时在 Provider 调用前 fail closed，不以截断输入冒充完整语义审核。

返回值必须是严格的 `accept | revise` JSON。`accept` 不得包含 finding；`revise` 必须包含 1-8 个带优先级、对应要求、问题和修正方向的 finding。无效 JSON、空结论、矛盾 verdict 或 Provider 失败都不能发布 Artifact。

模型 Reviewer 之前还有一个不调用 Provider 的父版本保留门槛。当前 Artifact Revision 是保守的“在父稿上修改”合同：父正文达到 1,000 字符时，候选至少保留 50%；父段落达到 10 个时，候选至少保留 80%；章节、表格和表格行数量不得下降。失败以可执行 finding 返回 Integrator，并计入同一有界修订预算。它专门阻止“修两句话却删掉大部分原稿”的静默退化；大幅删减或替换应新建 Artifact，未来显式 replace 模式另行设计。

## 3. 有界修订与恢复

Reviewer 的 `revise` 作为最终写入工具的失败反馈返回给 Integrator，复用既有 Artifact Gate 三次预算。候选未通过时：

- 不写临时目标文件，不进入 Artifact Registry，不发 `artifact.created`；
- Integrator 可以根据私有 checkpoint 中的具体 finding 重新生成候选；
- 三次仍被退回时，以有界错误结束，不继续消耗 Provider；
- 同一 Run checkpoint resume 不重置三次预算，已经用完的 Run 不会再调用 Reviewer；
- Integrator 没有任何一次最终写入成功时，不能只返回“完成”并让 Task 成功。

确定性父版本门槛与模型 Reviewer 使用相同的 `review_completed` 状态投影，并额外记录 `deterministicGate=parent-retention`；事件不包含父正文、候选正文或具体 finding。

事件只保存 `review_requested / review_completed / review_failed`、候选哈希、计数和 verdict。具体 finding 留在本机私有 Task checkpoint，`tool.failed` 和顶层失败事件只保存通用摘要，避免把 Reviewer 模型正文复制进 append-only Event Store。

## 4. Desktop 可见性

Desktop 的 Artifact 面板显示审核中、已通过、退回次数或审核失败；运行轨迹显示请求、通过或退回的有界摘要。该状态来自事件投影，不以 Renderer 内存为真源。

本切片没有加入人工 override。Reviewer 连续拒绝或无法形成有效结论时 Run 失败；用户可以检查私有 checkpoint/诊断后，从原请求安全恢复或新建 Run。未来的“接受 / 退回 / 带理由覆盖”属于独立人工 Review 决策合同，不能用当前自动重试冒充。

## 5. 脱敏 benchmark trace

完成或失败的 Run 可执行：

```bash
pnpm benchmark:trace -- WB-02 <workspace> <run-id> <new-target-json>
```

导出目标必须不存在且位于一次性 benchmark workspace 之外；macOS/Linux 使用 `0600`。输出包含 benchmark/case 身份、应用版本、Run 状态、Provider ID、时间、调用/token/失败计数、失败 Task ID、按工具名汇总的失败次数、Reviewer 状态、Artifact 元数据、事件计数和 checkpoint 状态。

输出明确省略 Goal、验收文字、模型内容、工具参数、错误正文、Artifact 正文、凭据、工作区名称和绝对路径。原始私有 Run 仍按清理策略删除，脱敏 trace 作为 scorecard 的诊断附件保留；它不能替代最终 Artifact、截图或人工评分。

## 6. 真实 Research Desk 任务加固

真实长资料任务必须维持两层资料边界：

- Run 的 Source Set 表示用户本次明确允许读取的全部资料；
- 每个 Worker 只看到计划分配给自己的逻辑 source ID，Runtime 对跨 Task 读取同样 fail closed；
- 长文本只能对一个明确逻辑文件调用有界 search_source_text，不能把“搜索正文”重新实现成遍历整个资料目录；
- `search_source_text` 可对单个已选 UTF-8 或受限 DOCX 做正文搜索；DOCX 先走本地安全解包和可见文本抽取，不把 ZIP 字节交给模型；
- Orchestrator 必须覆盖全部已选 source ID。遗漏时控制器在 Plan Review 前明确补入“使用或说明排除”的检查要求，不能静默丢资料；
- Orchestrator 输出格式错误允许一次有界修复；失败仍保留为规划失败，不直接启动 Worker。

恢复预算按“用户主动继续”与“单次模型循环”分开。单次 Agent 仍有 8 个 model turn 上限；用户从安全 checkpoint 继续时，只给未完成 Task 新增一个同样有界的继续窗口，已经成功的 Worker 不重跑，Reviewer 的三次语义退回预算也不重置。工具参数格式错误不冒充 Reviewer 退回。

数字闸门只拦截真实派生计算。URL、日期、政策原文中的百分数和 source-2/3/4 这类逻辑资料编号不是除法；校验器必须先识别这些领域标识，再判断是否需要 calculation ID。

Desktop 的 Goal Contract 默认可完整编辑，但用户可显式收起为结果、约束、验收和资料数量摘要；收起只改变布局，不改变将要提交的合同。

DOCX 修订仍使用有界 Markdown 作为 Provider-facing 参数，本地编译成 OOXML。父 DOCX 抽取文本中的 tab-separated 表格行可直接恢复为表格；普通段落之间必须保留空行，避免编译器把多个父段落合并。

## 7. 有意未覆盖

- Markdown/JSON/TXT 和 Coding patch 的独立语义 Review；
- 人工接受、退回或带理由 override；
- Reviewer 多模型交叉验证、引用逐条解析或事实数据库；
- 超过当前上下文上限的分块 Reviewer；
- 明确允许大幅删减父稿的 replace revision 模式；当前应新建 Artifact；
- Windows Word、LibreOffice 或真实 Provider 三次连续稳定性结论；
- 真实任务一次成功后的 token/调用次数优化与确定性 Integrator 内容编译；
- 自动提交、Push、Tag、Release 或生产发布。

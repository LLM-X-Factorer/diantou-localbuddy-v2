# M3.3 Safe Recovery and Worktree Lifecycle Specification

## 1. 目标

M3.3 解决两个本地长期运行问题：应用异常退出后不能把悬空 Run 留成“仍在运行”，以及 Coding Run 的 detached worktree 不能无限积累。

本阶段采用可验证的 request replay，不声称具备模型 turn checkpoint resume。

## 2. Run Request 持久化

每次执行在创建 Provider、请求模型或调用工具之前，原子写入：

```text
.localbuddy/runs/<run-id>/run-request.json
```

版本 1 契约包含：

- `runId` 与 canonical workspace；
- 用户原始 goal；
- research/code mode 与并发数；
- `createdAt`；
- `runtimeOwner`（desktop/cli）；
- replay Run 的 `recoveryOf`。

读取时重新验证 Run ID、字段范围、时间和 canonical workspace。Request 含用户目标，是本地私有状态；`.localbuddy/` 必须被 Git 忽略。

## 3. 中断对账

Desktop 在 bootstrap/list 时扫描当前 workspace：

1. 跳过当前进程 `DesktopRunManager` 仍持有的 active Run；
2. 跳过已有 `succeeded`、`failed`、`cancelled` 或 `interrupted` 终态的 Run；
3. 只处理存在有效 Request 且 `runtimeOwner=desktop` 的 Run；
4. 追加一次 `run.interrupted`，记录原因、模式、Request 创建时间和 replay availability。

事件追加后即成为终态，后续扫描不会重复追加。Desktop 使用 Electron single-instance lock；CLI owner 不由 Desktop 自动判定为中断。

## 4. 安全重放

只有 `interrupted` 且尚未产生 `run.restarted` 的 Run 可以重放：

1. 重新验证旧 Run Request 与 workspace；
2. 生成新的随机 Run ID；
3. 先持久化新 Request，并写入 `recoveryOf=<old-run-id>`；
4. 在旧 Run 追加 `run.restarted { newRunId }`；
5. 用同一 goal、mode 和 concurrency 从头执行新 Run。

旧 Run 的 event log 不修改，新 Run 不继承模型对话或任务内存。一个旧 Run 只能通过 UI 重放一次。

## 5. Worktree 清单与保护

`workspace.created` / `workspace.removed` 构成 Run worktree inventory。清理必须同时满足：

- Run 已达到终态且不在 Desktop active map；
- Integration 不处于 `awaiting_approval`、`approved/applying`、`applied` 或 `recovery_required`；
- 候选路径位于 `<repo>/.localbuddy/worktrees/`；
- 路径来自本 Run 的 `workspace.created`，且没有后续 `workspace.removed`；
- Git `worktree list --porcelain -z` 仍登记该精确路径。

若路径不在 Git registry 但目录仍存在，拒绝用普通递归删除兜底。若目录和 registry 都已不存在，只追加 `workspace.removed { alreadyMissing: true }` 完成对账。

Desktop 原生确认框默认取消。确认后使用 `git worktree remove --force`，允许删除 Worker 留下的未提交隔离改动；Run Request、event log、patch 和其他 Artifact 永远不在清理范围内。

## 6. 非目标

- 不持久化完整模型消息、tool-call continuation 或 task executor checkpoint。
- 不从中断模型 turn 继续；replay 会产生新的模型调用和可能不同的结果。
- 不自动重放，不在用户未操作时产生新的 LLM 成本。
- 不跨 Desktop/CLI 进程共享全局并发槽或 workspace lease。
- 不清理受保护 Integration 依赖的 worktree。
- 不删除整个 `.localbuddy/runs/<run-id>/`。
